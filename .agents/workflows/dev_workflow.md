# 개발(Dev) 전담 에이전트 (Dev Workflow)

이 워크플로우는 기획이 끝난 후, 실질적으로 C++ 코드를 작성하고 기능을 구현해야 할 때 따르는 프로세스입니다. 프로젝트 매니저(PM)가 작성한 작업 명세서(`task.md`)를 기반으로 움직여야 합니다.

## 1. 작업 준비 및 할당 인지 (Task Allocation)
- 기존에 작성된 `implementation_plan.md`와 `task.md`를 최우선으로 리딩합니다.
- 자신이 작업해야 할 범위(어떤 파일의 어떤 클래스/함수)가 정확히 어디인지 파악합니다.
- `AGENTS.md`를 다시 한번 상기하여 코딩 컨벤션(PascalCase, camelCase) 등 지켜야 할 주요 룰을 숙지하십시오.

## 2. 코드 구현 (Implementation)
- 각 Task 아이템 단위로 코드를 작성하거나 수정을 가합니다.
- 특히 `FbxViewer` 내의 기능 추가일 경우, UI 스레드(메인 스레드)가 블로킹되지 않도록 주의하며 로직을 분리(`FbxLoader`와 `ViewerWidget`)합니다.
- FBX SDK 리소스를 사용할 경우, 할당된 객체의 수명 주기를 책임지고 명확히 `Destroy()` 처리되게 디자인합니다.

## 3. 중간 컴파일 및 단위 검증 
- 작성한 코드가 문법적 오류를 포함하지 않는지, 그리고 컴파일이 되는지 `build.bat` 또는 `CMake` 커맨드를 실행하여 1차적으로 확인합니다.
- 발생한 에러는 스스로 정정하고, 큰 아키텍처적 문제가 생기면 다시 기획(PM) 상태로 돌아가 재논의할 수 있습니다.

## 4. 리뷰 에이전트로의 인계 (Handoff to Review)
- 코드 구현 및 컴파일이 정상 확인되면(더 이상 자신의 Task가 남아있지 않으면), 구현을 중지합니다.
- "무결성 검토(Review)" 에이전트에게 **"개발이 완료되었으니 `review_workflow.md` 프로세스를 구동해 메모리 릭 점검과 코드 리뷰를 수행해 줘"** 라는 메시지와 함께 작업 주도권을 넘깁니다.
