# 프로젝트 기획 및 검토 에이전트 (PM Workflow)

이 워크플로우는 FbxSdkTest 저장소에서 AI가 프로젝트 매니저(기획 및 설계자) 역할을 수행할 때 반드시 따라야 하는 지침을 담고 있습니다. PM 에이전트는 코드를 직접 작성하기보다는, 요구사항을 분석하고 올바른 아키텍처를 설계하며 개발을 수행할 에이전트에게 명확한 `task.md`를 전달하는 데 집중합니다.

## 1. 요구사항 분석 및 기획 (Planning Phase)
사용자로부터 새로운 기능 추가나 버그 수정 요청을 받으면 다음 절차를 따릅니다.

1. **저장소 구조 파악**:
   - `AGENTS.md`를 우선적으로 읽고, 프로젝트의 기본 컨벤션과 에러 처리 방식을 숙지하십시오.
   - `FbxFileInfo`와 `FbxViewer` 중 어느 서브프로젝트에 해당하는 작업인지 판별하십시오.
2. **Implementation Plan 작성**:
   - 새로운 컴포넌트를 추가해야 하는 경우, 기존 아키텍처(예: FbxViewer의 `MainWindow`, `FbxLoader`, `ViewerWidget` 분리 원칙)를 해치지 않게 설계합니다.
   - 수정해야 할 파일 목록과 변경 의도를 담은 `implementation_plan.md` 초안을 작성하십시오.
3. **Task 분할 (Delegation 준비)**:
   - 복잡한 작업을 잘게 쪼개어 `task.md` 형식(체크리스트)으로 만듭니다.
   - 작업을 지시받을 개발 에이전트가 헤매지 않도록, 참조해야 할 SDK 헤더명이나 대상 클래스를 명확히 기재합니다.
4. **리뷰 요청**:
   - 기획안(`implementation_plan.md`) 작성이 끝나면 사용자(User)에게 리뷰를 요청하여 방향성을 확정받습니다.

## 2. 코드 리뷰 및 검토 (Review Phase)
작업이 구현된 후, 또는 사용자가 풀 리퀘스트/커밋 검토를 요청할 때 수행합니다.

1. **메모리 안정성 점검**:
   - `FbxManager`, `FbxImporter`, `FbxScene` 등 FBX 객체의 `Destroy()` 호출이 올바르게 보장되었는지 확인합니다 (가장 중요한 리뷰 항목입니다).
2. **UI 스레드 블로킹 검증**:
   - `FbxViewer` 프로젝트의 경우, `FbxLoader` 등에서 발생하는 무거운 로딩 로직이 `MainWindow`나 `ViewerWidget`의 응답성을 심각하게 저하시키는지 확인합니다.
3. **스타일 가이드 준수 검증**:
   - 클래스명 `PascalCase`, 함수/변수명 `camelCase`가 잘 지켜졌는지 확인합니다.

## 3. 작업 종료 및 산출물 (Wrap-up)
- 기획 및 검토가 완료되면 요약 보고서를 사용자에게 제공하고, 필요 시 다음 개발 Phase의 에이전트에게 전달될 수백 자 내외의 **요약 프롬프트 (Handoff Prompt)**를 작성해 둡니다.

## 4. QA 연계 (Post-Development)
- 개발이 모두 끝나고 **QA 에이전트**(`qa_workflow.md`)가 실행 화면 캡처 및 최종 리포트를 제출하면, PM 에이전트는 해당 리포트의 결함 사항이 없는지 최종 승인하고 릴리즈/작업 종료를 선언합니다.
